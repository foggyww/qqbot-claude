# Error Handling

## 总原则

- 外部 API、文件 IO、WebSocket、子进程调用必须处理错误。
- 面向用户的错误消息应友好、简短、避免泄漏内部细节。
- 面向日志的错误可以更详细，但不能包含密钥、token、cookie 或完整私有配置。
- 禁止吞掉错误后无日志、无返回、无恢复。

## 插件和路由

- 插件 `onMessage` 异常必须被捕获并记录，不能阻断其他插件或主路由。
- 命令 handler 的错误应转换为用户可理解的响应。
- 权限不足、群未白名单、未 @bot 等场景应按 spec 决定静默或提示。

## MCP 工具

- MCP 工具失败应返回结构化 `error` 字段，避免未处理异常穿透。
- QQ MCP 工具只能通过 `QQAdapter` 访问 QQ 能力。
- 第三方 HTTP API 不得假设响应一定是 JSON：应检查 HTTP status、content-type，并捕获 JSON parse 错误。

## 子进程和 Claude Code

- Claude Code 子进程参数必须明确拆分，不能依赖 shell 拼接。
- 超时、退出码异常、stderr 应被记录并转换为可诊断错误。
- 路径相关错误应输出安全的路径信息，不输出密钥环境变量。

## 配置和文件

- 配置文件缺失、格式错误、权限不足时应给出明确错误。
- 运行时数据只能写入 `runtime/` 相关目录。
- 写文件前应确保父目录存在。
