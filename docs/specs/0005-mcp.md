# Spec 0005: MCP

## Status
Accepted

## Scope

项目内 MCP Host、内置 QQ MCP server、插件 MCP server。主要涉及 `src/mcp/host.ts`、`src/mcp/qq-server.ts`、`src/plugin/index.ts` 和插件提供的 MCP server。

## Goals

- 让 Claude Code 通过统一 MCP Host 调用 QQ 和插件工具。
- 防止 MCP 工具绕过核心 adapter 或生命周期。

## Rules

- MCP Host 必须随 `Bot.start()` 启动，随 `Bot.stop()` 停止。
- 内置 QQ MCP server 必须复用当前 `QQAdapter`。
- 禁止 MCP server 自己创建新的 QQ/OneBot 连接。
- 禁止调用旧 Python HTTP API。
- 插件如需 MCP，应通过 `Plugin.mcpServers` 暴露。
- Claude Code 使用的 MCP config 必须根据当前已注册的 MCP servers 动态生成，不能只硬编码内置 server。
- MCP server name 必须唯一，重复名称应在启动时失败或明确报错。
- MCP Host 应限制请求体大小，避免异常大请求耗尽内存。
- MCP 工具失败应返回结构化错误，不能泄漏密钥。
- 记账写工具必须携带有效的短期调用标识，由 Bot 的真实 QQ 消息上下文注册并传入 Claude HTTP MCP 配置；AI 返回的消息文本不作为可信身份来源。
- Host 校验记账写操作的 `source_id` 属于当前消息，操作序号为 1–100。无上下文的定时任务或其他 AI 调用可以查询，但不能写账。调用结束、超时或停止后标识立即失效。
- 保留显式 `owner_qq` 的可信用户跨账户语义；短期上下文用于防止伪造消息去重键，不替代账户授权设计。

## Behavior

- 默认 endpoint 是 `http://127.0.0.1:8765/mcp/<server>`。
- Host 可通过 `QQBOT_MCP_HOST`、`QQBOT_MCP_PORT` 覆盖监听地址和端口，但在没有远程认证机制时监听地址必须是 loopback。
- 内置 `qqbot` MCP server 提供发消息、查群、查成员、查历史、撤回、用户映射等工具。

## Error Handling

- JSON-RPC 请求格式错误应返回协议错误。
- 工具参数无效应返回明确错误。
- Adapter 调用失败应转为工具错误响应。

## Security

- MCP 监听默认本机地址。
- 未配置认证的 MCP Host 必须拒绝监听非 loopback 地址，避免远程绕过 QQ 路由权限。
- 工具不得返回完整私有配置或密钥环境变量。
- QQ 操作权限应由上游对话权限和工具设计共同限制，不能提供任意越权入口。

## Tests

修改本范围时应考虑增加 MCP host/server 测试，并至少执行：

- `npm run typecheck`
- `npm test -- --run`

## Acceptance Checklist

- [ ] QQ MCP 仍复用 `QQAdapter`。
- [ ] MCP 生命周期仍由 Bot 管理。
- [ ] 工具错误是结构化的。
